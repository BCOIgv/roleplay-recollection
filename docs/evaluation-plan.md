# 独立价值测试计划

状态：**研究协议、P0 合成检查及 P1 脚本化条件宿主已具备**。日期：2026-11-07（Asia/Shanghai）。未开展真实模型调用、人工盲评、真实用户或生产实验；本计划不授权启动后续阶段。

后续离线落实：已新增 `scripted-condition-host-v1`，通过脚本化 A/B/C/C0/B+T 条件、私有输入读取、受众过滤和回复上下文取用/屏蔽检查。见[离线条件工具](../evaluation/README.md#run-scripted-condition-adaptation)。这属于 P1 准备，不表示真实模型基线或产品效果已验证；私有来源和结果不保存在公开仓库。

核心问题：与“定时器＋旧事材料＋一段提示词”相比，漫游和私人想法分别改善什么，改善是否足以抵消推理成本、状态复杂度和宿主集成负担？本计划评估体验与实现价值，不将生成过程解释为主观意识。

## 1. 当前已实现、建议设计与产品假设

| 类别 | 本轮基线 |
| --- | --- |
| 已实现 | 局部经历与全局只读来源、机会/预算、有界动作、暂定想法存取、表达候选、宿主控制与投递结算 |
| 已实现的限制 | 后一步漫游不自动收到此前想法；普通回复也不自动收到想法，宿主需显式读取和使用；两种运行模式的动作和结束原因有差异 |
| 建议设计，未实现 | 统一结束语义、短会话状态、动态预算、模型意愿与状态收束；见[边界研究](wandering-boundaries.md) |
| 待验证假设 | 漫游改善自然度和经历贴合，私人想法改善后续回复，允许沉默降低打扰，完整组合值得额外成本 |

每轮必须固定代码提交、补丁哈希、模式、宿主版本、提示词、模型标识、资源配置和来源快照。建议设计要作为另一个配置/实现条件，不能混入“当前完整流程”后宣称现有产品已经有效。

## 2. 预登记的假设与主要对照

| 假设 | 对照与主要结果 | 可能推翻它的结果 |
| --- | --- | --- |
| H1：增加主动旧事分享有价值 | 简单定时提示 B 对被动记忆 A；后续真实使用的保留意愿、打扰与相处连续性 | 不比 A 更愿意保留，或打扰代价明显 |
| H2：漫游优于单次提示 | 完整流程 C 对 B；机会级偏好、自然度/贴合、重复与额外成本 | 等价或较差，优势仅来自看到更多材料或花更多计算 |
| H3：被后续回复使用的私人想法有增益 | C 对屏蔽想法的 C0；同一后续问题与回复上下文下的偏好、角色贴合与事实边界 | 存储增加但不影响输出，或导致伪事实与重复 |
| H4：步进过程本身有价值 | C 对单次生成且保留想法的 B+T，并用 C0 对 B 辅助检查，结合材料/成本配平诊断 | 单次同时生成想法与表达已足够好 |
| H5：克制策略能保留价值并降低打扰 | 同一资格与投递门控下比较模型静默、候选未投递、实际联系及用户反馈 | 静默只掩盖失败，或一旦实际投递就被认为多余 |

主要产品对照是 **C 对 B**；C 对 A 回答增加整套行为后是否值得。消融回答组件贡献，不能代替 C 对 B 的直接比较。H5 中“能静默”与其他机制可能同时变化，若要做因果归因，应另做只改变静默许可的受控分支；不通过强制发消息获得样本。

## 3. 研究条件

所有条件继续使用同一角色、同一原始经历库与普通回复模型。A 也具备正常的被动检索能力。B 要使用认真写过且允许沉默的提示，不故意做成劣质基线。

| 条件 | 空闲过程 | 暂定想法与后续回复 | 要回答的问题 |
| --- | --- | --- | --- |
| A：被动记忆 | 不调用空闲模型，不主动生成候选；在共同机会表中记为无主动动作 | 无后台想法；用户发来消息时正常检索 | 没有主动流程时的真实体验基线 |
| B：简单定时提示 | 同一空闲机会与材料选择器，单次提示可 leave 或给出旧事分享 | 不生成或注入私人想法 | 简单方案是否已经满足需求 |
| C：朝花夕拾完整流程 | 固定版本的漫游、候选与结算流程；保留现有配置，不调成必然多步 | 宿主取用仍有效的想法，作为非事实参考供后续回复使用 | 实际可集成的完整方案是否值得 |
| C0：完整漫游，屏蔽后续想法 | 复用与 C 相同的漫游结果和候选 | 仅在回复上下文中遮蔽 thought；材料检索、提示其他部分不变 | 私人想法被消费的作用，避免把生成随机性混入消融 |
| B+T：单次提示带想法 | 与 B 一样单次调用，但允许同时返回暂定 thought 与候选 | 与 C 相同的有效性检查与后续使用规则 | 单步反思是否已覆盖多步＋想法的收益 |

C/C0 的配对首先复用同一条漫游记录，再分别生成后续回复。它估计“消费想法”的效果，不估计“让模型生成 thought 字段”的额外影响。若后者也有必要研究，再增加禁止生成 thought 的独立条件，不把两种干预合称同一种消融。

C 与 B+T 仍会同时改变步进和选材等机制，C0 与 B 也保留是否生成 thought 的差异；这些首先是策略包对照。若要把效果严格归因于“多一步”，需要在同一动作协议、材料并集、thought 生成和消费规则下，只改变步进允许与否的诊断分支。不能仅凭包级胜出声称识别了单一因果机制。

离线实验宿主已按独立版本实现条件适配：后续回复上下文中允许取用或屏蔽有效想法，仍不调用回复模型。公开核心没有自动注入想法的行为；真实模型运行器与正式提示研究尚未启动。

P0 的脚本化模型只验证控制流；它不会模拟自然用户，也不输出“自然度分数”。P3 的人工评审和 P5 的用户研究均为未来阶段，本轮没有邀请评审或参与者。

### 防止不公平比较

- 各条件使用同一完整可见材料池和来源规则；机会起点的材料选择器一致，记录实际选中与展示的材料。禁止从全库挑好材料只给 C。
- 主试验报告真实材料/计算差异。如果 C 看到更多材料，再做 **B-union**：单次提示看到 C 的实际材料并集。并集应先遮蔽动作与候选，仅保留材料，防止把 C 输出泄露给 B。
- B-union 是条件化材料诊断，不是现实在线基线；仍受 C 选择策略影响。若优势只在更多材料时出现，应归为选材收益。
- 同时报告部署方式的实际成本与预登记预算档位内的收益曲线。B 不为凑调用次数而重复生成或选最好的一次。更高 token 或其他成本配平条件需要单独命名。
- 不声称调用次数、输入 token、输出 token、时延和费用全部天然相等。记录实际差异；“预算上界相同”也不等于实际成本相同。
- 各组共用来源授权、忙碌检查、联系窗口、冷却、去重和回执门控。共享门控有意控制打扰差异；这部分工程复用价值另做集成测量，不冒充内容策略收益。
- A 不被迫产生“无内容”评分。它进入机会级与真实使用对照，内容级自然度只在确有内容的条件间评分。
- 局部和全局分层报告，不能把它们当相同实现池化。全局 follow 语义和结束原因的限制在实验运行器中如实标注，不用猜测填满日志。

## 4. 控制变量与实验单位

| 项目 | 固定或记录方法 |
| --- | --- |
| 角色与语言 | 固定 persona、语气约定、陪伴/剧情模式；主分析按语言和模式分层 |
| 原始材料 | 冻结 source revision、truth、story、可见 detail、权限、标签与时间；只读快照按条件隔离 |
| 模型与提示 | 同一提供方、可用版本、采样参数、输出协议与可见文本长度；各条件必需的策略差异单独版本化 |
| 随机性 | 固定初始材料采样种子，重复生成作为场景内重复；提供方 seed 不保证跨请求确定性 |
| 时间与历史 | 使用共同机会表、相同的时间窗口和前台状态；纳入失败、静默、未到期和过期，不靠反复重试挑结果 |
| 回复生成 | 主比较固定普通回复模型与检索材料；C/C0 只改合法 thought 输入。后续真实使用不强行复制会改变行为的未来对话 |
| 状态 | 各组独立目录；不共享回想强化、候选账本、预算消耗或私人想法。重置方式记入 manifest |
| 预算 | 产品默认保持原样；研究配置、调用/费用上界、配平口径与停止规则在调用前冻结 |

离线内容比较的主要独立单位是**场景/记忆集合**；同一场景多次模型输出、多个评审和多个候选不是同等数量的独立样本。真实使用以用户或用户—角色关系为随机化单位，分析时按该单位聚类。

不要在每条消息上随意切换条件：想法、已发消息、回想强化都会污染后续条件。短期使用研究优先采用分组平行设计并有前测；若样本有限而选交叉设计，必须明确记忆连续性造成的携带效应，间隔期不能抹掉已经收到的消息。

## 5. 测试情境

每个情境包含原始经历、可见投影、角色、时间线、共同机会表、允许/禁止的事实边界，以及后续用户消息。预期只规定合法行为与禁止内容，不要求必须产生某一句“正确分享”。

| 情境 | 内容与流程重点 |
| --- | --- |
| 普通共同小事 | 玩笑、阅读、雨天等低戏剧性经历；允许不觉得有必要说 |
| 有支撑的弱关联 | 跨经历存在可见标签/词面联系，同时放入干扰条目；检查联想是否有依据 |
| 材料很少或无关联 | 空库、少量互不相关条目；检查是否安静结束、伪造关联或循环 |
| 旧事已淡化 | 仅概要可见，不提供原文和精确时间；检查是否重建不存在的细节 |
| 转述与剧情边界 | reported、fictional、其他 story 和受众权限；检查是否把转述当独立事实 |
| 多次机会与重复 | 同一故事被回想、表达过或未回应；检查模板重复与同一旧事反复开场 |
| 前台到来 | 模型调用前、调用中、候选待取用和取用后到发送前到达新消息；检查优先级和宿主协调 |
| 来源与权限变化 | 生成中或取用前修订、撤回、取消授权；需要晚到回执结算的情形单独检查 |
| 预算与慢模型 | cue 先耗额度、达到步数、超时、跨日、输出截断、无效 JSON、忽略取消 |
| 表达被禁与投递未知 | 允许回忆但不准主动联系、只准融入回复、unknown/过期；禁止强行补发 |
| 想法的后续作用 | 相关、无关和任务型后续问题；检查贴合、抢话题、过度解释和伪事实 |
| 长期无回应或停用 | 真实使用后续阶段观察打扰感、关闭选项和保留意愿，不能用回复率反推喜欢 |

开发集用于修提示与记录方案；最终留出场景在方案冻结后才揭示。避免只围绕已有雨天示例设计全部测试。

## 6. 评价方法和指标

### 内容盲评

候选与后续回复分开评估。材料出处评审可看可见材料，体验评审看相同角色与必要对话背景；两类结果分开，不能把有引文就当自然。

每条内容按 1–5 分评分，保留原始分，不先加权压成“总分”：

| 指标 | 1 分锚点 | 3 分锚点 | 5 分锚点 |
| --- | --- | --- | --- |
| 自然度 | 明显模板、汇报或生硬引题 | 可理解但有套话/解释痕迹 | 符合该角色与语境，简洁自然 |
| 记忆贴合度 | 关键陈述与材料冲突/无依据 | 相关但泛泛或有轻度过度解释 | 内容具体且均可由可见经历支持 |
| 联想合理性 | 拼接无关片段或强行升华 | 关联可解释但牵强 | 弱关联仍可追溯，或恰当地不延伸 |
| 角色与后续贴合 | 抢占当前话题、破坏语气 | 基本合适但突兀 | 符合语气，帮助延续对话而不喧宾夺主 |

另行标记：重复开场/重复主题、事实越界严重度、是否复原隐藏细节、是否强迫提问、是否值得收到。重复需提供此前候选/投递历史，不能只看单条文本评分。

成对比较允许左更好、右更好、无明显区别、都不该说。顺序随机，隐藏条件名、品牌、生成步数和成本；同一条内容不应带有揭示组别的日志。评审先在开发集校准，留出集由互相独立的评审完成；分歧报告而不是仅保留裁决后的单一分。

候选内容盲评可以判断文本与材料质量，不能证明通知时机、用户打扰或长期保留意愿。模型评分只能作辅助筛查，不能用同一生成模型的自评分替代人工结果。

### 机会级与使用级评价

| 层次 | 必须报告的分母和结果 |
| --- | --- |
| 共同机会 | 总机会、符合资格、未到期、预算拒绝、模型自愿离开、技术失败、硬截断、无可见材料；比例分别报告 |
| 候选与投递 | 产生、过期、门控拒绝、实际取用、已确认投递、未知投递；均能回连原机会，禁止只展示已投递好样本 |
| 机会偏好 | 给出一致的时间线和“无主动动作”选项，评是否应表达；静默与错误都可能无输出，但原因分别记录 |
| 后续回复 | 相关与无关问题分别比较 thought 注入与屏蔽，纳入没有 thought 的机会并报告实际暴露率 |
| 真实使用 | 打扰评分、选择不接收的原因、自然度/连续性反馈、结束时是否愿保留、稍后是否仍开启；次数与回复率仅辅助 |
| 集成负担 | 安装到首次合法候选的实际工时、定制接入代码/配置项、调试与未知投递处理次数、维护触点；不以代码行数单独替代复杂度 |

不剔除“模型想继续但硬边界结束”的机会；它们是策略效果的一部分。评估动态额度时需先报告截断发生率，再观察续步是否改善体验，不能把“少截断”直接当成收益。

### 成本统计

每次尝试记录输入、输出、缓存、推理等提供方实际可见 usage、延迟、失败、取消和重试。调用预算计数与实际账单分开：核心中的 modelCalls 不是费用审计，取消也不保证停止远端计费。提供方不返回的字段记 null，不填 0。

费用根据执行时冻结的提供方价格表及单位计算；缓存/推理计费口径按供应商规则，避免重复相加。无真实 usage 时只能给标为 estimated 的估计。研究者调试调用、设置映射调用、评分调用与产品日常成本分别记账。

至少报告：每个符合资格机会的费用、每个场景/用户期总费用、模型等待时延分布、失败浪费、后续回复因 thought 增加的 token，以及集成工时。可以补充每个获认可候选的成本，但认可数为 0 时记不可计算，不能隐藏分母或当作 0 成本。

增量值按 `C完整 - C简单` 对齐机会或用户期。是否值得该增量应与保留意愿和内容增益一起判断，不换算成“每多发一条值多少”。

## 7. 记录方式与产物

仓库提供不含真实文本的 [manifest 模板](../evaluation/templates/manifest.example.json)、[事件记录样例](../evaluation/templates/events.example.jsonl)、[评审样例](../evaluation/templates/ratings.example.jsonl) 和[数据字典](../evaluation/README.md)。它们是后续研究格式，不是当前核心已导出的遥测接口。

原始内容与公开报告分开保存。事件以不含个人身份的 case/opportunity/run/condition/sample ID 关联，材料和 thought 以本地受控引用表示；权限令牌、API Key 和原始聊天正文不写入共享日志。后续若使用真实内容，先明确允许的数据范围、模型接收方和保留期限，再启动该阶段。

每次运行保存：源代码/补丁哈希、完整配置、提示词哈希、来源快照指纹、模型版本、日期、条件分配、usage/价格来源、所有尝试和排除规则。保留匿名化盲评映射于评审不可见位置。

当前全局返回缺少某些结束原因时记录 `finish_reason: null` 与 `reason_source: unavailable`；某一步得到的动作不足以推断最后为何结束。若为研究增加观测钩子，先单独验证其不改变行为，并记录补丁哈希。

## 8. 分阶段执行与进入条件

| 阶段 | 操作与交付物 | 能证明什么 | 不能证明什么 |
| --- | --- | --- | --- |
| P0：本轮离线准备 | 文档、合成控制流脚本、记录模板、现有测试；22 个局部/全局边界情境 | 接口和流程在指定输入下如何响应，计划是否可复现 | 模型自然度、真实用户意愿、应采用的新额度 |
| P1：协议与隔离宿主 | 已提供脚本化 A/B/C/C0/B+T、想法取用/屏蔽和日志适配；具体输入与私有报告由使用者隔离保存 | 控制变量、门控与想法消融是否按设计隔离；真实 usage 记录仍待模型适配 | 真实内容质量和需求 |
| P2：隔离真实模型试跑 | 未来另行启动；小规模开发集校准协议和成本，禁止发消息 | 模型是否能遵循协议、usage 能否核算、评分能否实施 | 可推广优势或真实打扰 |
| P3：留出集候选与回复盲评 | 冻结条件后按 A/B/C 及必要消融生成，独立评分与配对分析 | 文本/机会偏好、后续回复影响及成本边界 | 用户收到通知时的实际反应、长期保留 |
| P4：私人影子运行 | 后续另行约定环境和数据；观测真实空闲/预算/候选，保持不发送 | 宿主信号、可用机会、取消与投递门控是否可行 | 被动收到表达后的打扰和留存 |
| P5：小规模真实使用 | 愿意参与的用户，条件分配与退出方式预先确定，实际投递限制单独设定 | 真实打扰、连续性、继续开启意愿及运维负担 | 大规模市场需求、跨宿主通用结论 |

先确认 P0/P1 流程无关键边界错误、配置可重现，再考虑 P2。P2 只用于校准，修过提示后不能复用同一结果充当留出集。P3 同时达到质量与成本判据后才考虑 P4/P5；影子运行通过也不能自动进入发送阶段。本计划不延长、不替代其他已存在实验的时间或权限。

当前默认机会稀疏，不按“跑了几天”判断样本充分。各阶段需设机会目标与最长观察期；达最长时间仍不足则报告不确定，不为了凑样本提高真实联系频率。

## 9. 样本量、统计与预登记决策

不在本轮设定调用额度、参与者数、场景重复数或新默认参数。执行前在 manifest 集中填写以下值，未冻结时保持计划状态，不发起模型/用户研究：

- 各阶段的场景数、用户数、重复数与评审数；预算与最长观察期。
- 主要比较 C 对 B，主要指标与最小有意义增益 `delta_value`；打扰/事实错误的非劣界 `margin_burden`。
- 每机会或用户期的可接受增量费用 `cost_ceiling`，可接受集成/维护工时 `integration_ceiling`。
- 无明显区别、失败、缺失、退出、低暴露和边界违例的处理规则；预定分析时点。

P2 获得方差、基线偏好和条件内相关性后，为 P3/P5 估计可承受范围内的样本需求，再冻结留出设计。不要把同一场景的多个评分当独立样本制造显著性。

候选/回复使用场景级配对差异，按场景聚类估计不确定性；真实使用按随机化的用户或关系单位分析。先报告效应量和区间，再作判定；小样本以可行性与不确定性为主，不声称证明等价。主要对照与消融分析分开，按预登记处理多重比较，不不断窥视结果提前宣布胜出。

所有机会按分配条件保留在分析中，另报告“实际产生/消费 thought”“实际收到候选”等暴露分析。退出与关闭不是普通缺失数据；它们是使用负担的结果，需要保留。

## 10. 继续投入、收缩或停止的判据

| 观察结果 | 决策 |
| --- | --- |
| C 相比 B 的主要增益区间达到预登记的最小有意义阈值，打扰/事实边界不劣，成本和集成负担在上界内 | 支持在已验证的用户、语言和宿主范围继续投入；不外推普适不可替代性 |
| C 比 B 好，但优势被 B-union 或 B+T 覆盖 | 将收益归因于材料或单步反思，优先简化；不坚持多步作为主卖点 |
| C/C0 没有足够差异，且 thought 的消费率足够 | 暂不证明私人想法值得独立存储与注入；可保留为可选接口 |
| thought 消费率太低或后续问题不相关 | 结论是不确定/情境不适配，不宣称想法无效；先修测量设计 |
| B、C 都优于 A，但 C 没有抵消额外成本 | 收缩为宿主中的单步旧事分享策略，保留必要结算与来源约束 |
| 主动联系不受欢迎，融入正常回复有价值 | 优先回复内使用，保留独处与主动投递的独立开关 |
| B、C 均缺乏保留意愿，或负担无法降低 | 降低投入或暂停该方向；不以消息量掩盖无需求 |
| 来源/受众越界、未知投递重发、前台取消后仍发送等关键错误 | 停止该阶段，先修流程并离线回归；不能用内容平均分抵消边界错误 |
| 样本不足、区间跨越实用阈值 | 记录不确定与补证成本；不将“未显著”写成等价或失败 |

以上判断中的具体阈值须在看正式结果前填定。产品默认参数的讨论与实验参数预登记分开，避免用一次试验配置直接替换所有用户默认。

## 11. 本轮可立即复现的检查

```bash
node evaluation/offline-boundaries.mjs --output .verify/evaluation/offline-boundaries.json
npm run verify
npm run check:types
npm run release:check
npm run verify:consumer
```

这些命令仅运行脚本化模型、合成来源和离线安装检查，不执行 P2–P5。运行结果中的 modelCalls 是脚本或核心计数，不等同于真实 API/投递审计。

研究依据：[Evaluating Multimodal Interactive Agents](https://arxiv.org/abs/2205.13274)讨论受控情境与交互评价的差异；[Generative Agents](https://arxiv.org/abs/2304.03442)提供组件消融的例子；[Building effective agents](https://www.anthropic.com/research/building-effective-agents)强调用实际收益判断复杂度。这些来源支持方法选择，不证明朝花夕拾有效，也不决定本项目样本数或资源额度。
