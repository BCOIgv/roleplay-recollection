# 独处设计

> 适用版本：roleplay-recollection 0.3.0。独处是核心内置流程，不依赖定时器、后台服务或平台适配。

## 1. 为什么需要独处

如果角色只在用户说话时「检索相关记忆」，它看起来仍然是一个被调用的工具。独处把主动回想从「单次相关度检索」改成一段**没有任务、没有听众、可以随时结束**的过程：

- 记忆可以自己浮上来，不必有用；
- 可以停留、顺着弱关联走、换念头，也可以马上离开；
- 想起一件事，不等于要说出来；
- 如果真的想分享，先结束独处，再等待合适的搭话时机。

这样做的目的不是增加消息量，而是让角色有一点「不围着用户转」的内部生活。

## 2. 机会调度

独处不是每次空闲都发生。机会由持久化计划控制：

| 项目 | 默认值 | 说明 |
| --- | --- | --- |
| 基础间隔 | 72–120 小时 | 每次结束后重新随机抽取，不是固定周期 |
| 新增经历加速 | 12–20 条 | 新增的独立经历达到阈值，可提前**同一次**机会 |
| 最短间隔 | 48 小时 | 加速也不能早于上次结束 48 小时 |
| 加速后再等 | 2–8 小时 | 给「刚发生的事」一点沉淀时间 |
| 有效窗口 | 10:00–22:00（上海） | 落在窗口外时顺延到下一个窗口内的随机分钟 |
| 机会有效期 | 24 小时 | 到期只跳过一次，不补跑 |

调度规则：

1. 首次计划在构造函数中生成并持久化；重复检查或重启不会重新抽签。
2. 新增经历只影响**当前**这一次机会；达到阈值后只计算一次 `growthAt`，不会叠加成多次机会。
3. 如果加速时间早于原 `dueAt`，则用加速时间；否则保持原计划。
4. 机会过期时写入一条 `opportunity_expired` 历史，然后重排下一次；不会把错过的独处补成积压任务。

## 3. 进入条件

宿主调用 `solitude(context)` 时，核心依次检查：

| 条件 | 不满足时的结果 |
| --- | --- |
| 陪伴或剧情模式，且角色/范围/故事匹配 | `skipped` / `different_context` |
| 宿主提供真实的 `lastInteractionAt`，且已空闲 ≥ 45 分钟 | `waiting_for_quiet` |
| 没有 `busy`、`userAwaitingReply`、`hasPendingWork` | `conversation_has_priority` |
| 当前处于 10:00–22:00 上海时间 | `waiting_for_quiet` |
| 没有暂停、没有进行中的回想/独处 | `paused_or_busy` |
| 机会已到期且未过期 | `not_due` / `opportunity_expired` |
| 今日模型预算未用完 | `model_budget` |
| 配置了 `wander` 适配器 | `no_thinker` |

`lastInteractionAt` 必须由宿主提供；核心**不会**把「没有收到消息」自动当成用户空闲。

## 4. 漫游循环

每次独处最多 `maxWanderSteps` 步（默认 2，可配置 1–3），并有 `solitudeMinutes` 分钟上限（默认 10）。

每一步：

1. 从当前可见记忆中取 `memoriesPerStep` 条（默认 2，可配置 1–2），排除本次已访问的记忆；
2. 把记忆（只含当前可见内容）交给 `wander`；提示词明确说明：没有任务、没有读者、没有结论要求、没有消息配额；
3. 等待一个 JSON 决策：`leave / linger / follow / switch`；
4. 记录访问；如果带 `thought`，保存为暂定私人想法；如果带 `shareText`，立即结束独处并生成联系意愿。

动作语义：

| 动作 | 含义 | 下一步 |
| --- | --- | --- |
| `leave` | 现在离开 | 结束，零输出也正常 |
| `linger` | 停留在当前记忆 | 下一步仍看同一段 |
| `follow` | 顺着弱关联走 | 下一步优先与当前记忆有词面/标签重叠的记忆 |
| `switch` | 换一个念头 | 下一步随机/加权取其他记忆 |

约束：

- 模型输入不包含用户当前问题、聊天记录或「必须回复」的指令。
- `anchor` 必须是当前可见文本的精确子串；引用未见过的记忆会被拒绝。
- 每步模型调用**先计数再调用**；失败/超时也计入当日预算。
- 访问过的记忆不会在同一次独处中重复出现；`linger` 除外。
- 同一段记忆在一次独处中最多强化一次，避免反复刷高激活度。

## 5. 结束与联系意愿

独处可能以这些原因结束：

`left_quietly`、`wants_contact`、`time_limit`、`step_limit`、`no_more_memories`、`model_budget`、`thinking_failed`、`interrupted`、`interrupted_or_deadline`、`opportunity_expired`、`superseded`。

结束时：

1. 清除 `inflight`；
2. 写入 `solitude.history`（最近 30 条）；
3. 重排下一次机会（重置 `lastEndedAt`）；
4. 如果本次有效且模型给出了 `shareText`，生成一条 24 小时有效的**联系意愿**；它只是候选，不是已发送消息。

重要：**只有独处结束后才生成联系意愿**。独处进行中想起什么，不等于可以立刻打断去说。

## 6. 取用与回执

联系意愿的状态流转：

```text
pending ──takeExpression──> taken ──settleExpression──> sent / used_in_reply / not_sent / unknown
   │
   └──过期或来源失效──> expired_or_stale
```

取用条件：

- `allowExpression` 为真；
- 没有待处理工作；
- 非「融入正常回复」的取用，还要求不忙、用户不在等回复、已空闲且处于时间窗；
- 同一时间最多一个 `taken` 或 `unknown` 的独处意愿，避免多路主动投递；
- 联系冷却：
  - 默认 48 小时；
  - 用户上次回复晚于上次联系时，仍按 48 小时；
  - 未回应时延长到 72 小时；
  - 同一段旧事 7 天内不重复作为开场。

回执规则：

| 结果 | 要求 | 是否消耗联系额度 |
| --- | --- | --- |
| `sent` | 真实平台 `receipt` | 是，更新 `lastContactAt` |
| `used_in_reply` | 必须通过 `delivery:'reply'` 取出，并提供正常回复回执 | 是 |
| `not_sent` | 确认没有发送 | 否 |
| `unknown` | 投递结果未知 | 不重发，并阻止新的主动投递，待核实 |

`settleExpression` 对已结算的同一结果幂等；重复调用不会重复计冷却。

## 7. 中断、失败与并发

- 用户来消息、宿主标记忙碌、暂停、来源修订/撤回/不可用、`close()` 或 `AbortSignal` 都会中止当前独处。
- 中断后**不恢复**，也不会补跑剩余步骤；下一次机会重新排。
- 模型超时/失败按 `thinking_failed` 结束；失败尝试仍计预算，不立即重试。
- 晚到的模型结果不能提交：运行 token 的 epoch 已变化，结果被丢弃。
- 持久化写入使用锁与原子替换；进程崩溃留下的过期锁会在 PID 不存在时回收。

## 8. 参数

| 参数 | 默认 | 范围 | 作用 |
| --- | --- | --- | --- |
| `solitudeIntervalHours` | `[72, 120]` | 48–336 | 基础间隔（小时） |
| `growthThreshold` | `[12, 20]` | 1–500 | 新增经历加速阈值 |
| `growthDelayHours` | `[2, 8]` | 0–24 | 加速后的额外等待 |
| `minimumSolitudeHours` | `48` | 1–168 | 两次独处最短间隔 |
| `inactivityMinutes` | `45` | 0–240 | 进入前的对话空档 |
| `activityHours` | `[10, 22]` | 0–24 | 允许进入的上海时间窗 |
| `maxWanderSteps` | `2` | 1–3 | 单次最多步数 |
| `memoriesPerStep` | `2` | 1–2 | 每步取几条记忆 |
| `solitudeMinutes` | `10` | 1–10 | 单次时限 |
| `dailyModelCalls` | `2` | 1–8 | 与线索回想共享的每日模型预算 |
| `expressionIntervalHours` | `48` | 1–168 | 联系冷却 |
| `unansweredContactHours` | `72` | 1–336 | 未回应时的冷却 |
| `sameMemoryExpressionDays` | `7` | 1–60 | 同一旧事重复间隔 |

## 9. 取舍与非目标

- 不拥有定时器：宿主决定何时轮询/调用；核心只维护「下一次机会」。
- 不自动发送：只产生候选和意愿，真实投递与回执由宿主完成。
- 不测量情绪：`importance`/`emotionalWeight` 是调用方给的角色设定，不是心理测量。
- 不追求「每次独处都有产出」：离开、沉默、零笔记都是正常结果。
- 不做完整人格成长、好感度经济或模拟人生。

## 10. 验证

`test/solitude.test.mjs` 覆盖 19 项独处定向行为，包括：

- 机会持久化、重启不重抽、过期不补跑；
- 新增经历加速且不叠加、批量导入只产生一次机会；
- 忙碌/等回复/最近活动/缺少活动证据时不启动；
- 随机采样不是总选最高重要性；
- 用户问题不进入独处输入；
- 停留、弱关联、换念头与离开；
- 淡化记忆不泄露隐藏细节；
- 每日预算与线索回想共享；
- 任务信号中断、模型失败不立刻重试；
- 分享意愿只在结束后产生、不消耗联系额度；
- 未回应冷却、过期、正常回复消费、未知投递不重放；
- 来源撤回使待用意愿失效；
- 重启把中断的独处当作已结束，而不是重放。

合计 56 项离线检查（54 项既有 + 2 项存储锁回归），全部通过。真实模型自然度与平台投递仍未验收。
