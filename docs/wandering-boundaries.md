# 有界漫游：当前限制、结束机制与候选方案

状态：**设计研究，尚未更改运行逻辑或默认参数**。日期：2026-11-07（Asia/Shanghai）；代码基线 `65ef240`。本页中的数值已按当前 src/policy.mjs 复核，核心默认值保持原样，不是新默认值建议。效果验证按[测试计划](evaluation-plan.md)推进。

时间线评测运行器另有 2000 tokens 的 API allowance、选材和想法注入；这些属于实验宿主，并非核心配置变更。历史 live 的记录缺口见[实验摘要](../evaluation/results/README.md)。

## 已实现：实际边界与相互作用

| 边界 | 当前默认与允许范围 | 影响与需要观察的问题 |
| --- | --- | --- |
| 单次步数 `maxWanderSteps` | 默认 2，配置范围 1–3 | 最后一轮还要求 follow/linger 时，也可能直接被循环上限截断 |
| 每日调用 `dailyModelCalls` | 默认 2，范围 1–8；按上海日切分，与线索回想共享 | 不能把“单次最多 2 步”理解为每次保证能跑 2 步；先发生的线索回想可能用掉额度 |
| 每步材料 `memoriesPerStep` | 默认 2，范围 1–2 | 局部和全局都会把展示过的材料加入 visited，即使模型只引用其中一条；小材料池可能提早耗尽 |
| 会话时限 `solitudeMinutes` | 默认 10 分钟，范围 1–10 分钟 | 是接受结果的截止边界，不代表模型持续思考这么久，也不是整个进程的强制终止器 |
| 单次调用 `modelTimeoutMs` | 默认 30000 ms，范围 50–60000 ms | 模型超时会结束本次等待；钩子忽略取消时，远端计算与计费仍可能继续 |
| 输出预算 `maxOutputTokens` | 默认 500，范围 64–800 | 同时影响动作 JSON、暂定想法和表达的可生成空间；它不是步数或产品自然度的度量 |
| 文本长度 | 想法最多 400 字符，表达最多 160 字符 | 独立于 token 限额；超长或无效动作按失败处理，当前无自动修复调用 |
| 独处机会 | 基础间隔 72–120 小时，另有增长加速、空闲时长和活动窗口 | 影响机会是否发生；不能与单次漫游长度混为同一个额度 |
| 联系冷却 | 默认间隔、未回应间隔、同一旧事间隔，以及候选有效期 | 影响候选是否可取用；增加漫游额度不能绕过发送资格 |

同一预算日、没有其他并发消耗时，可执行步数最多受 `min(单次步数上限, 剩余每日调用)` 约束，还会被模型离开、表达出现、材料耗尽、取消、超时等提前结束。跨日预算重新计数是另一个状态变化，不能单凭开始时的余额推断整个会话上限。

当前两条路径的实现见 [局部独处](../src/solitude.mjs)、[全局运行](../src/global-core.mjs)、[参数校验](../src/policy.mjs) 与[调用取消](../src/model.mjs)。

## 已实现：局部与全局并不完全等价

| 行为 | 局部 `CompanionMemory` | 全局 `GlobalRecollection` |
| --- | --- | --- |
| 漫游动作 | leave/linger/follow/switch | 另接受 silence/keep/express；这些也可能结束循环 |
| follow | 使用词面/标签重叠提高关联材料权重 | 当前不使用局部的弱关联加权；继续从剩余材料取样，不能宣称两条路径语义完全一致 |
| linger | 复看当前焦点，下一轮可能只提供该条 | 保留焦点到材料列表首位，仍可能附带其他材料 |
| 暂定想法 | 保存，可通过 privateThoughts() 获取 | 保存并绑定受众，可通过 privateThoughts() 获取 |
| 下一步模型输入 | 不自动包含此前保存的想法或完整漫游轨迹 | 同样不自动包含此前想法或完整轨迹 |
| 出现分享文本 | 结束并可形成待取用联系意愿；实际取用仍受权限与情境约束 | 文本出现会结束；只有 allowExpression 为真才保存表达候选 |
| 前台更新 | 重新调用局部 solitude 并报告 busy 等状态可中断局部独处，也支持 AbortSignal | 新一次 busy 调用会被跳过，但不等于取消原调用；宿主须传递原调用的 AbortSignal 或控制入口 |
| 结束可观测性 | 返回 step_limit、model_budget、left_quietly 等原因；取消也可能以 solitude_ended + interrupted 返回 | 部分正常结束仅返回 solitude_ended，没有详细原因；某些截止时间拒绝归入 stale_source |

因此，不能仅凭 `solitude_ended` 认定“自然结束”，也不能把缺少 reason 当成“模型愿意离开”。默认步数和日预算同时为 2 时，局部结果的 step_limit 也不排除预算刚好用完：需要记录所有同时生效的边界。

尤其需要区分两件事：**保存了私人想法**已经实现；**私人想法自动推动下一步漫游或后续回复**尚未实现。后续回复需要宿主显式读取、校验并使用它。增加调用次数不会自动补上这条信息通路。

busy/hasPendingWork 是调用时的状态快照，不是平台消息订阅。宿主必须建立前台事件到在途请求取消的连线；仅在自己的内存里改变一个布尔值不会被核心自动感知。

## 必须保留的工程边界

| 边界 | 必须保持的性质 | 数值或策略是否可讨论 |
| --- | --- | --- |
| 对话优先 | 宿主更新忙碌状态或传递取消后，禁止提交失效的晚到输出；投递前重新检查情境 | 检测与传播方案可改，优先级不能交给模型覆盖 |
| 来源与受众 | 仅使用授权、仍有效的可见材料；想法不能提升为事实或扩大权限 | 可见投影可演进，权限边界不可被联想绕过 |
| 资源有上界 | 会话、账户或角色范围内有可核算的调用/时间/成本上界，异常不无限重试 | 上界数值、计量单位和分配方式待讨论 |
| 运行与投递分离 | 候选不是已发送；unknown 不自动重放，回执与状态变更应可核对 | 冷却与过期策略可研究，不伪造成功回执 |
| 取消与幂等 | 已终止会话不因晚到结果复活；重启不自动补发未决消息 | 可以研究新的恢复协议，不能隐式恢复旧会话 |
| 随时安静结束 | 不设置必须表达、必须生成想法或必须用满预算的最低产出 | 可记录原因，不把沉默作为失败处罚 |

预算边界不能等同于“固定跑满若干步”。模型可以决定更早结束，但不能自行授权更多资源或实际投递。

## 可能过于僵硬的限制

1. **步骤上限和日预算重叠**：上限相同会掩盖截断原因；共享预算还可能让独处被线索回想挤占。先观察各自的约束频率，再决定额度，不直接把增加上限当作修复。
2. **只改变材料，没有显式的会话状态**：前一步想法不会进入下一步输入。更多调用可能变成多次相互独立的旧事采样，而非更连贯的漫游。
3. **已展示即 visited**：模型未选择的条目也被排除；同时，linger 又可多次复看同一焦点。前者可能过早耗尽，后者可能机械重复。
4. **分享文本立即结束**：这有助于克制输出，但在全局表达权限关闭时，仍可能终止且不保留候选。应明确这是“回想已结束”还是“只禁止表达”，不由额度间接决定。
5. **动作词暗含不同终止含义**：全局 keep 会结束，本地保存 thought 后仍可 follow。仅统一配置数字并不能统一行为。
6. **机会窗口、预算日和会话截止时间耦合**：时间跳变、跨日、前台恢复可能改变行为。不能只测试模型始终快速返回、额度始终充足的顺利路径。

这些是设计与可观测性问题，不是已经证明的自然度损失。当前证据只能说明哪些控制流可截断过程。

## 候选方案与取舍

| 方案 | 建议设计，均未实现 | 收益假设 | 成本与风险 |
| --- | --- | --- | --- |
| A：先统一语义和结束记录 | 区分模型自愿离开、表达就绪、硬截断、前台中断、来源失效、协议失败；记录同时生效的限制，明确两种运行模式动作含义 | 先知道为何结束，避免对错误指标调参 | 需要观测与状态约定；自身不保证内容更自然 |
| B：硬上界内的自愿结束 | leave 随时有效；继续意愿只是一项输入，宿主结合剩余资源和状态决定能否再步进；到硬边界直接结束，不强制补一句话 | 避免“固定跑满”，又给尚有联想的过程留下可配置空间 | 模型可能倾向持续 follow 或过早 leave，仍需重复/停滞检测和硬上界 |
| C：动态资源分配 | 以 token、实际用时、预计费用和调用次数组成上界；是否为独处预留份额、是否允许借用共享额度另行决定 | 减少一次短调用与一次长调用被视作等成本的问题 | 需要使用量回执、原子预留与并发结算；取消不代表远端费用归零 |
| D：短会话状态 | 向下一步提供有限的已访问引用、上一动作与短暂定关联；保持来源、受众和有效性绑定 | 多步之间可能更连贯，而不只是重新抽样 | 更多输入 token，重复强化与伪事实风险；应作为独立实验变量 |
| E：状态驱动收束 | 可见材料失效、前台恢复立即结束；确切循环或无变化重复触发收束；有明确停留意愿时不以“没有新事实”强制结束 | 减少机械来回，又保留普通小事与安静停留 | “无变化”判据若过强，会把漫游重新变成效率任务 |

推荐研究顺序是 **A → 在现有资源边界内明确 B → 分别验证 C/D/E**。这只是设计顺序，不是授权实施的新策略或新默认值。持续后台思考、自动扩额、多次主动消息与自动续跑都不作为本轮结论。

### 建议的结束优先级

以下是待实现设计，可作为后续协议评审顺序：

1. 宿主撤销、前台到来、受众/来源失效：中断，丢弃不再有效的待提交结果。
2. 硬资源上界或会话截止时间：结束；不为“最后总结”额外调用模型。
3. 模型自愿离开：正常安静结束。
4. 表达就绪：进入候选生命周期；是否同时结束、表达被禁时是否只存想法，需要明确约定。
5. 继续意愿：只有剩余资源、有效材料和宿主许可都满足才允许继续。
6. 重复或停滞：依据明确状态指纹收束；不要求每步产出新知识或对用户有用。

自然结束、硬截断和错误要分别统计。中断可以保留此前已经提交且仍有效的暂定内容，但不能把后来被取消的生成补交为新内容。

## 离线流程证据与能证明的范围

执行：

```bash
node evaluation/offline-boundaries.mjs --output .verify/evaluation/offline-boundaries.json
```

脚本使用内存经历、全局合成来源、脚本化模型和可控时钟，对两条路径分别检查安静结束、双重上限、共享预算、前台阻止、取消、截止时间、想法存取、表达开关和 linger，共 22 个流程情境。测试中的配置覆盖仅用于区分现有约束，没有修改默认参数。

已观测到：默认双重上限可同时生效；先消耗一次线索回想后，剩余日预算会截短漫游；保存的想法未自动进入下一步；表达开关和结束原因在两条路径存在差异；取消或过期的晚到分享未形成候选。

这些结果证明当前流程如何响应指定输入，**不能证明多步更自然、私人想法更有价值或应增加额度**。公开返回缺少详细结束原因时，报告保留 null，不伪造自然结束标签。

## 研究依据与外推限制

- [Anthropic：Building effective agents](https://www.anthropic.com/research/building-effective-agents)：支持保留停止边界，并通过结果验证额外复杂度；它讨论任务型 agent，不能据此给本项目选出漫游数量。
- [LangGraph Graph API](https://docs.langchain.com/oss/javascript/langgraph/graph-api)：条件路由与递归边界可以并存。其 super-step 与本项目模型调用不是同一单位，不迁移其默认数值。
- [Generative Agents，UIST 2023](https://arxiv.org/abs/2304.03442)：提供记忆、反思、规划组合与消融思路；其社会模拟任务不等于本项目的无指定产出漫游，也不证明当前策略有效。

边界优化与独立价值验证应分开：即使控制流更合理，仍要按[测试计划](evaluation-plan.md)与简单定时提示进行对照。
