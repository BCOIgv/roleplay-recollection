- 最新 WorkBuddy 批次中，C 的三次后续回复均收到含“桂花乌龙”的 anchoredMemoryText，但三条回复均未明确说出“桂花”或“乌龙”，仍多为调暗屏幕、热水等建议。是否更自然、更贴合不能由“找到材料”推出，也不能用泛化的“发呆/休息”措辞证明独特收益。

## 研究限制

1. **桥接是实验宿主的一部分。** 场景显式设置 surface_ids/bridge_id；有效时选择器把该桥接材料排到第二步，缺失时使用宿主的词面启发式。全局核心本身的 follow 只是继续采样剩余材料。C 的提示还鼓励第一步 follow、第二步收束。这是受控机制探针，不是自然产生关联的成功率测试。
2. **展示材料和提示没有配平。** C 可以看到更多材料，B+T 只有第一步材料，尚无 B-union 对照。B/B+T 的独处提示有近期上下文，C 的核心输入没有相同字段。不能把差异单独归因于“多想一步”。
3. **想法注入不是核心默认行为。** 时间线宿主自己维护最多 maxThoughts 条想法并附加原记忆文本；公开核心的 privateThoughts 最多返回三条，且全局接口只给文本。当前评测版本已限制被核心拒绝的想法进入实验台账，但这项离线修复不能追溯算作历史 live 行为。
4. **默认关闭主动开场。** 已记录批次 proactive_open=false。B 的候选不进入回复，故其回复与 A 近似拥有同样信息。没有真实投递，无法判断主动联系收益、打扰程度或保留意愿。
5. **不是严格配对的回复消融。** C/C0 共享独处，但各自生成的回复会进入本组后续历史；越往后上下文越可能不同。不能将后续差异归为单一 thought 开关的因果效应。
6. **版本记录不足。** 两个完整时间线报告都标 host-v1，但 b86f7b 没有原记忆文本注入，a4d481 有；实际 API 输出上限也曾调整，旧报告仍记录钩子的 500。旧记录没有代码哈希或独立实际上限字段，无法精确重建所有历史实现。当前 host/runner-v2 新增快照、哈希和实际上限字段，只做了离线检查，没有对应的新 live 结果。
7. **样本与审阅范围有限。** 三条人工场景、每条件一次生成、非盲审阅，且用开发结果反复调整过提示。135 次回复不是 135 个独立场景。没有留出集盲评、真实用户或生产验证；不能宣称“100% 不犯错”“跨供应商稳定”或“不可替代”。

## 复核方式

在持有原始合成报告的本地工作区运行：

```bash
node evaluation/audit-results.mjs --runs evaluation/reports/runs --output .verify/evaluation/recorded-runs.json
```

汇总器只接受标记为 synthetic 的 live 报告，输出字段经过白名单筛选。生成物需人工复核后才能替换公开摘要。它不运行模型、不评分自然度，也不读取私有记忆备份。

下一阶段需要冻结宿主/提示/预算，补齐相同材料与门控的对照、独立场景与盲评，按照[研究协议](../../docs/evaluation-plan.md)判断体验收益。当前结论是：流程可执行，成本可记录，产品价值仍需验证。
